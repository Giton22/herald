# Screen plugin (release candidate, not yet reviewed)

A same-origin Hermes gateway viewer for Bot Desktop, with explicit observation/control handoff and protected selection Copy. Kyllene integrates an optional native Android WebView clipboard bridge; its use requires an app build that includes the integration. Without it, clipboard availability depends on the browser and platform. No installation or activation is performed by this package.

## Requirements and configuration

- A compatible Hermes gateway with in-process dashboard plugins, stock gateway WebSocket ticket authentication, display RPC/lease and display WebSocket APIs. The manifest's minimum version is inherited from the prototype, not a verified compatibility claim. See https://hermes-agent.nousresearch.com/docs .
- `fastapi`, `aiohttp`, `anyio`, and a compatible Hermes Bot Desktop with TigerVNC. The Python packages are declared in `plugin.yaml`, without version bounds because compatible versions across target Hermes installations have not been established. Current Hermes package management resolves plugin dependencies with core constraints and may request consent; older versions may only report them, so verify they are installed in the gateway's Python environment. This is not a guarantee that an arbitrary resolved version is compatible. Protected local Copy additionally needs Python `tkinter`, X11, and the normal profile-scoped lease and Xauthority files; it is not a Wayland selection reader. The plugin bundles no desktop server and does not automatically install a runtime.
- Observation accepts `gateway`, `terminal:docker`, and `terminal:ssh` placements, the inspected Hermes built-in stream-capable backends. Other placements, including stream-capable third-party plugins, fail closed pending capability verification. Hermes itself decides whether the configured desktop can start and forwards sandbox RFB through its display endpoint. Protected Copy is **unavailable on sandbox screens** and never falls back to gateway X11.
- Set `HERMES_SCREEN_GATEWAY_PORT` in the gateway process to the decimal TCP port on which **that same gateway** accepts plain HTTP WebSockets on IPv4 loopback. An unset, invalid or out-of-range value causes RPC admission to fail closed. The operator must control and verify this trusted port: session cookies and one-use tickets are sent before any upstream identity check, and a malicious local listener can capture them. Loopback is not upstream authentication. TLS-only or Unix-socket-only upstreams are unsupported. The URL is fixed to loopback and cannot be set from a browser request.
- Install the `herald-screen` directory for the gateway's launch profile using that profile's supported Hermes plugin workflow. The inspected Hermes version does not route user-plugin WebSockets to secondary profiles; selecting a secondary profile in a shared dashboard is not supported by this candidate. A separate gateway launched for another profile has not been tested. Configuration and restart/reload depend on the deployment. Plugin activation and HTTP auth/consent must be enforced by Hermes before its routes run.

Kyllene's one-click setup requests installation and enablement only; it does not configure the port or install TigerVNC or a desktop. An enabled plugin is not proof that Screen is ready. Configure and verify the trusted same-gateway port and desktop separately before use.

The plugin binds itself to the gateway's active `get_hermes_home()` at import and rejects requests if that active profile changes. The RPC relay permits only Screen methods and forwards original cookie, Host, Origin, and one-use ticket to the configured gateway before accepting a browser socket. Display uses the stock gateway display endpoint. Selection reads require the authenticated observing transport and current human lease before and after the read. Access to the desktop is sensitive; use authenticated encrypted access across untrusted networks. No separate public listener is created. Do not run multiple profile gateways against each other's upstream port.

**Accepted placement race:** observation and the latest received `display.status` are snapshots, not an atomic placement lock or generation fence. If placement changes from gateway to sandbox after the observed gateway placement and before or during the local X11 read, without a status update reaching the relay in time, Copy can read and return a prior gateway-local screen's selection instead of the displayed sandbox screen. The before/after authoritative lease checks do not eliminate this race; even status checks cannot detect an unreported or delayed transition. A reported non-gateway status clears the binding and blocks local Copy, but does not make the read atomic. Avoid Copy during placement changes; eliminating the risk requires an atomic profile- and placement-bound selection operation or equivalent fence from Hermes.

Each RPC connection accepts at most 8192 distinct valid request IDs; an invalid or reused ID, or any further request after the limit, closes it. Reconnecting starts a fresh ID budget and a fresh authenticated observation; pending requests are not resumed, and control must be established again before Copy. If a handoff or disconnect leaves the hold uncertain, the viewer fences input and may require explicit recovery; reconnection does not itself establish that the agent has resumed.

### On-demand start interface

The viewer checks status on explicit open or Retry and requests start if the desktop is stopped; automatic reconnection does not start a stopped desktop. Start has a 90-second RPC deadline; after an ambiguous timeout the viewer makes bounded status checks rather than automatically issuing another start. After a successful running status it observes the screen and redeems the one-use display ticket. The authenticated Screen RPC socket accepts the stock `display.start` JSON-RPC method with empty `params` and a unique ID, scoped to the gateway's launch profile. Clients should invoke it only on explicit user request. Start is forwarded to Hermes, which owns idempotence and lifecycle; the relay does not take control, stop a desktop, change configuration, or automatically start on observation. Errors are deliberately generic. The viewer disables Copy on supported sandbox placements; backend rejection remains authoritative. A stopped desktop cannot be observed before start.

Viewing does not automatically take control: the user selects Take control and can Hand back. Disconnect or refresh attempts to hand back control; reconnect uses a fresh viewer identity and starts watch-only. The relay stops forwarding and queues owner-bound releases on the same RPC connection, relying on the gateway's serial control processing to follow any in-flight acquire. Cleanup has a bounded deadline and is best effort: network loss, timeout, or a failed upstream can leave the old lease and its state unknown. Inspect or hand it back using Hermes Screen controls if necessary. The displayed lease status is a snapshot for user guidance, not a security guarantee: a concurrent human takeover between an update and an explicit click can still be displaced by Hermes's last-writer-wins acquire.

Local Copy is a one-shot request for the X11 PRIMARY selection while the user holds control, not automatic clipboard broadcast; the placement race above is accepted, not fixed. Sandbox Copy is unavailable until a supported Hermes selection API exists. Clipboard access also depends on browser or optional Android bridge support.

For a handoff, an agent can ask the user in existing Bot Chat. If Kyllene Push is configured, that existing path may notify the phone, but delivery is not guaranteed. This plugin neither sends the agent message nor implements a separate push notifier.

This candidate has not been tested against a live gateway or Android device after portability changes and is not deployment-ready. Multi-profile operation and secondary WebSocket behavior are not verified. Test the exact gateway version, profile isolation, reverse proxy, handoff and clipboard behavior before deployment.
