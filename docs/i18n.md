# Localization

Herald's words live in a catalogue, not in the code: `shared/ui/src/commonMain/composeResources/` holds one
folder per language, and the screens read from it through Compose resources.

```
composeResources/
  values/strings.xml      English: the source every other language is translated from
  values-de/strings.xml   German
```

`shared/ui` gets them through `implementation(compose.components.resources)` and names the generated accessor
in `build.gradle.kts` (`packageOfResClass = "dev.hermeskotlin.ui.resources"`), so a screen reads:

```kotlin
Text(stringResource(Res.string.settings_pure_black))
Text(stringResource(Res.string.settings_running_send_detail, runningSendSummary(mode)))
```

## Adding a language

1. Copy `values/strings.xml` to `values-<tag>/strings.xml` (`de`, `es`, `pt-BR`, …) and translate the text.
   Keep the `name` attributes and every `%1$s` / `%1$d` placeholder: the number of the placeholder is the
   argument, so dropping one loses it in the sentence.
2. Add the tag to `androidApp/src/main/res/xml/locales_config.xml`. Android 13 and later then list the language
   under Settings › Apps › Herald › Language; older phones follow the system language.
3. Leave a key out if the translation isn't ready: Compose falls back to `values/` for that key alone, so a
   half-finished language is a half-translated screen, not a crash.

A key that a screen references but the catalogue doesn't have is a compile error (`Res.string.foo` is
generated), so a typo can't ship. A key in `values/` that no screen references is dead weight; keep the
catalogue honest as the surface grows.

## Splitting words from logic

A screen whose text depends on state (which plugin version the gateway has, how many tools are on) keeps the
choice in a plain function and the words in the composable: `suggestionsLine` in `SettingsScreen.kt` returns a
`SuggestionsLine`, `suggestionsDetail` turns it into text. The test can then check the choice without Compose,
and a translation never has to parse a branch.

Plurals go through `<plurals>`, not `if (count == 1)`: `pluralStringResource(Res.plurals.x, count, count)`.

## What still holds its words in code

The catalogue covers Settings and everything it opens: Starting instruction, App icon, App lock, the phone
tool question, the plugin dialogs. The rest of the app is next, in slices of one surface at a time:

- chat, composer and the sheets over it
- sessions, inbox, rooms, capabilities, config
- Phone tools (`settings/PhoneToolsScreen.kt`)
- lines a view model builds itself, such as the connection check's stages and the wallpaper error

`docs/ROADMAP.md` keeps the item (`i18n.catalog`) unticked until those are in.
